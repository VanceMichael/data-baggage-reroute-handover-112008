# 跨航司签转时的行李交运凭据采集

这里是可离线启动的合成上游，所有编号、时间和凭据都用于联调。

本项目在地服侧增加一个**只读采集 + 人工核对**的工作台：读取票务签转、行李分拣、新航司受理、班次交接和地服双边报告，按旅客和逐件原条码给出「本次交运由谁接、证据缺在哪、下一步联系谁」，并区分可交接、待确认、必须人工处理。

它不负责订票，也不向行李设备下达装机/卸机命令；工作台登记的是“现场已经发生的退接/转交事实”，不是设备指令。

## 本地运行

使用 Node.js 22.23.4。项目只使用随 Node.js 提供的运行库。

```sh
npm test
```

两个终端分别启动合成来源与工作台：

```sh
# 终端 1：合成上游（票务/分拣/受理/班次/人工报告）
npm run start:source

# 终端 2：地服工作台，默认 http://127.0.0.1:4180
npm run start:workbench
```

打开 `http://127.0.0.1:4180`。点「采集/刷新」会按当前演练阶段重新取数。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `SOURCE_PORT` / `PORT` | `4173` | 合成上游端口，`SOURCE_PORT` 优先 |
| `WORKBENCH_PORT` | `4180` | 工作台端口，`PORT` 次之 |
| `SOURCE_URL` | `http://127.0.0.1:${SOURCE_PORT}` | 工作台读取的上游地址 |
| `WORKBENCH_STATE` | 未设置 | 认领与双边事实的持久化文件；未设置时仅保存在内存 |

上游默认地址为 `http://127.0.0.1:4173`，`GET /health` 用于确认来源服务已就绪。来源使用进程内演练时钟，启动时处于 `book`。用 `PUT /_source_clock?step=dispatch` 推进到下一阶段，`GET /_source_calls` 查看本实例收到的业务请求。可查阶段为 `book`、`dispatch`、`receive`、`withdraw`、`correction`。重启服务会重置时钟和请求记录。预置的源端回执按演练阶段出现，和本地应用是否已处理某次回执是两回事。

演练阶段对应地服需要判断的现场：

| 阶段 | 现场 | 工作台结论 |
| --- | --- | --- |
| `book` | 签转已出，分拣批次页未读完，受理页空且未完整 | `OA-01`/`OA-02` 待确认；提示“未出现不等于无此件” |
| `dispatch` | `OA-02` 已装机，受理页仍未到件 | `OA-02` 必须人工处理（自动依据停止），同组 `OA-01` 继续处理 |
| `receive` | 新航司逐件签收与拒收 | `OA-01` 可交接；`OA-03` 拒收必须人工 |
| `withdraw` | 票务撤销 `T7`，旧分拣点补传待交运记录 | `OA-01` 进入撤销恢复，收件凭据保留，补传不会把责任转回旧分拣点 |
| `correction` | 班次 `M1→M2`，双方登记退接 `T7/OA-01` | 恢复可交接；待认领交接班人，已认领按原操作人跟踪 |

## 工作台约定

- **按旅客 + 原条码看件**。票务的 `old`/`new` 是票号，不当作行李标签；新票标签不会覆盖已动作的原条码。分拣/受理给出新条码时，新条码只是这一件的新标识，原标签仍是关联键。
- **不合并**。不会因为航班号相同或旅客同姓就把资料合并；同一旅客同一原标签若出现多个航段，保持未关联并提示。
- **时间语义**。不同来源的时间不是全局序列；事件先后只在同一航段、交运链和原条码里按现场动作时间（`at`）解释。资料到达时间（`seen`）只用于说明重传/晚到。分拣 `seq` 只在自己批次页内递增。
- **空页 / 重传 / 拒收分开**。受理页 `rows=[] && complete=false` 是尚未到件；`rows=[] && complete=true` 是完整但为空，要追问；同一 `transfer+原条码` 的重复行合并，签收与拒收冲突标为人工。分拣页相同 `tag+state+at` 的重传只计一次现场动作。
- **装机扫描**。看到 `loaded` 就停在“本件自动交接依据停止”，需要联系装机复核班组确认能否抽回；不生成抽回命令，也不影响同组其他行李。
- **撤销**。签转撤销后原交接指令作废但保留依赖资料；已收件的行李不会随票自动回原航司，需经办人登记双边确认的退接/转交。
- **认领**。交接指令以「班次 + 交运链」认领，同一件行李同一时刻只有一个有效认领。只有可交接的件能认领；已认领的跟随原操作人，直到有现场凭据结案或经双方转交。班次交替后未认领事项交给接班人。

## 接口

工作台只读上游，接口都在本地：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/health` | 工作台与上游可达性 |
| `GET /api/view` | 采集上游并返回 `model` 与 `workbench` 视图 |
| `POST /api/claims` | 认领交接指令（`code`、`chain`、`shift`、`operator`） |
| `POST /api/claims/release` | 原认领人释放 |
| `POST /api/claims/reassign` | 双方转交（`from`、`to`、`acceptedBy`） |
| `POST /api/claims/resolve` | 有认领后现场凭据时结案 |
| `GET /api/facts` / `POST /api/facts` | 查看 / 登记双边确认的退接或转交事实 |

没有写票务、分拣或设备命令的接口；上游请求全部是 `GET`。

## 来源约定

票务 `/tickets/transfers` 提供按旅客代号与航段的改动。分拣 `/sorting/batches` 提供批次页地址，`/sorting/S8?page=1` 一类网页路径的 `next` 用于分批查看；序号由分拣点独立递增。`/receiving/handoffs` 列出接收批、旧原条码及可能分配的新条码。受理结果可以为各箱件独立填报，用签收时间标记现场动作，`seen` 是各来源自己的采集时间。
`/shifts/handover` 提供已交接的班组与联系人编号，`/reports/manual` 是可能晚到的地服现场双边确认，含交运号、原条码、双方以及移交用途。

## 目录

```
src/collector.mjs   上游采集（分页、超时、错误不伪造空资料）
src/model.mjs       只读判定（逐件状态、证据、指令历史）
src/workbench.mjs   认领、转交、结案与双边事实登记
src/server.mjs      工作台 HTTP 服务与静态页面
public/             工作台页面
sources/source.mjs  合成上游
fixtures/           合成资料
test/               来源、采集、判定与工作台测试
```
